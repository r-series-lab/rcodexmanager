# 界面与功能说明

rCodexManager 以 Profile 为主对象，将日常状态对比放在主工作区，将较重的会话、认证、渠道和路由操作放入四个按需加载的管理中心。公开截图全部由浏览器 mock 数据生成，只使用 `example.com` 账号和示例路径。

## 主工作区

主界面按列展示：

- **Profile**：显示名称、Profile 命令和独立工作区标识。
- **分类**：用于筛选不同用途的 Profile。
- **账号**：邮箱、套餐、组织和认证方式。
- **认证**：本地令牌状态与是否需要重新登录。
- **最近会话**：标题与更新时间，不读取完整会话正文。
- **额度**：按需查询 5 小时或 7 天窗口，不在启动时批量请求。
- **环境**：路径、配置和运行依赖是否正常。
- **状态**：运行中、已登录或未登录；归档视图显示已归档。
- **操作**：启动/停止、查看额度和更多操作；已归档 Profile 显示恢复与删除。

点击行只选择当前 Profile；双击打开完整编辑弹窗。右键菜单固定为启动/停止、编辑、归档和删除。归档只从活动列表隐藏 Profile，保留启动函数、认证、配置、会话和目录，可从“已归档”筛选中恢复。

工具栏提供全文搜索、分类筛选、智能/最近使用排序，以及全部、运行中、已登录、未登录、有会话和已归档状态筛选。额度按钮只查询当前可见页，避免无意中请求全部账号。

![Profile 主工作区](assets/screenshots/profile-workspace.png)

日常使用顺序：

1. 先用搜索、分类和状态筛选找到目标 Profile。
2. 看认证、模型、最近会话、额度和运行状态，确认是否需要登录、切换模型或停止实例。
3. 高频动作直接用行内按钮；认证、编辑、归档和删除等低频动作从 `...` 菜单进入。
4. 对默认 Profile 保持只读思路；需要实验、切换登录态或改模型时先创建自定义 Profile。

## 四个管理中心

四个管理中心共用标题栏、工具栏、主从布局、状态标签、空状态、错误恢复和底部操作栏。默认高度约为 App 可用高度的 80%，窄窗口会切换为列表/详情单面板。

### 会话中心

会话中心先读取有界的索引页，支持搜索、Profile、分类和 `10/50/100` 页容量，默认每页 10 条。选中一条会话后才读取对应 JSONL 的摘要与来源信息。切换筛选或关闭弹窗后，过期请求不会覆盖新结果。

![会话中心](assets/screenshots/session-center.png)

使用要点：

- 先筛选 Profile、分类或关键词，再调页容量。
- 只在需要阅读某条会话时点选该行；列表本身只展示索引和摘要。
- 复制给 AI 或同事时优先复制摘要、时间、cwd 和来源路径，不要直接倾倒完整 JSONL。

### 认证库

认证库管理用户已授权的 `auth.json` 备份。列表显示有效、损坏或文件缺失状态；详情提供备注、置顶、导入预检、导出、应用、回滚和重复清理。默认 Profile、运行中 Profile 和损坏备份不可作为写入目标。

![认证库](assets/screenshots/auth-vault.png)

使用要点：

- 备份前确认来源 Profile 已停止或至少不是正在写认证的状态。
- 导入外部包先做预检；只有预检通过后再应用到停止中的自定义 Profile。
- 应用登录态前确认目标、账号、来源和回滚记录；默认 Profile 不作为覆盖目标。

### 远程渠道

远程渠道统一管理微信与飞书：

![远程渠道](assets/screenshots/remote-channels.png)

- 微信按 Profile 区分未绑定、等待扫码、已绑定未运行、运行中和异常，支持启停、重启、脱敏日志与可恢复解绑。
- 飞书复用用户自行安装的 `codex-remote-feishu`，rCodexManager 只记录 Profile 和运行时路径，不保存 App ID 或 App Secret。

使用要点：

- 微信按 Profile 建实例；扫码、启停和解绑都只影响选中的 Profile。
- 飞书先在外部运行时完成配置，再由 rCodexManager 绑定 Profile 和二进制路径。
- 日志默认脱敏；遇到连接异常先刷新状态和读取最近日志，再决定是否重启。

### 模型路由

模型路由分为概览、配置和诊断。可以检查当前 Provider、模型、URL 和代理，测试草稿而不写文件，预览后再应用；应用与恢复前会备份 `config.toml`，不会修改 `auth.json`。桌面内置代理适合基础转换，也可以打开 cc-switch 使用外部代理。

![模型路由](assets/screenshots/model-routing.png)

使用要点：

- 先选停止中的自定义 Profile，再选择 Provider 模板、模型和 URL。
- 新供应商先运行草稿测试；远端节点只传 API key 的环境变量名。
- 点击“预览配置”确认实际写入内容；确认应用后再看自检结果。
- 恢复官方配置只移除路由字段，保留认证和会话。

## 新建、编辑与登录

“新增 Profile”提供启动命令、显示名称、分类、模型、推理等级和路径预览，可选择“仅创建”或“创建并登录”。编辑弹窗集中维护元数据、模型和运行路径；路径卡片支持复制完整路径或在文件管理器中定位。模型写入只允许停止中的自定义 Profile，并先备份配置。

本地登录使用 Codex 官方浏览器 OAuth；授权地址只保存在当前 App 进程内，完成、取消或过期后清除。

## 设置与诊断

设置面板管理亮色、暗色、跟随系统和中英文界面。运行诊断会只读检查启动配置、路径、进程、认证、路由、代理与渠道，并生成已脱敏的建议，不修改用户数据。

## 数据加载原则

- 主界面不预加载完整会话、认证库、渠道日志或模型路由报告。
- 管理中心打开后才加载对应资源，30 秒内优先显示内存缓存并后台刷新。
- 会话正文、日志和额度均按选择或明确操作读取。
- API key 只在模型路由弹窗内存中短暂存在，关闭或应用后清空。
